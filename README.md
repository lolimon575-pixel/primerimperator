# Император — демонстрация прямых заказов

Next.js 15, React 19, Node.js 24. Демонстрация: https://primerimperator.onrender.com. Кабинет: `/admin`.

## Что работает

- Меню, корзина, серверный расчёт по каталогу и проверка изменения стоимости.
- Сохранение тестовой заявки до показа номера. Повтор той же попытки возвращает прежнюю заявку.
- Кабинет администратора: журнал, фильтры, подтверждение, приготовление, готовность, завершение и отмена.
- Защита паролем, подписанный сеанс на 8 часов, HttpOnly-cookie, проверка Origin, ограничение запросов и защита от одновременного изменения статуса.

По умолчанию включён `ORDER_MODE=demo`. Контакты гостя заменяются вымышленными на сервере. Тестовые заявки не передаются в ресторан, не оплачиваются и не считаются выручкой. Демо-хранилище временное, до 1000 заявок, записи старше суток удаляются при приёме следующей заявки. Render может очистить его при перезапуске или обновлении.

## Запуск и проверка

1. Установить Node.js 24 и выполнить `npm ci`.
2. Скопировать `.env.example` в `.env.local`. Задать `ORDER_ADMIN_PASSWORD` длиной не менее 24 символов и отдельный `ORDER_RATE_LIMIT_SECRET`. Для локального запуска `ORDER_APP_ORIGIN=http://localhost:3000`.
3. `npm test` проверяет цены, дубли, сохранение, статусы, шифрование и доступ. `npm run build` проверяет производственную сборку. `npm run dev` запускает разработку; `npm start` — собранное приложение.
4. Дополнительная проверка работающего сервера: `ORDER_TEST_ORIGIN=http://localhost:3000 ORDER_TEST_PASSWORD=<пароль> node tests/http-smoke.mjs`. Скрипт работает только в демо-режиме, создаёт одну вымышленную заявку и доводит её до завершения. Пароль в командную строку лучше передавать через среду процесса.

На Render переменные добавляются к уже существующим. Секреты не хранить в репозитории. Текущий сервис автоматически развёртывает изменения основной ветки.

## Перед настоящим пилотом

Нужно согласовать с рестораном меню и цены, правила доставки, акции, предоплату, обработку обращений и фактический канал уведомлений. Уведомления, онлайн-оплата, POS-интеграция, аналитика продаж и редактирование меню в кабинете пока не подключены. Стоимость доставки и акции не включены автоматически в сумму по меню.

Публичная демонстрация на Render за пределами РФ блокирует рабочий режим. Для отдельного согласованного запуска в РФ нужны проверенное размещение базы в России (`ORDER_STORAGE_COUNTRY=RU`) и подготовленные документы оператора (`ORDER_LEGAL_READY=1`). Эти значения — заявления оператора, они не подтверждают соответствие закону сами по себе. Проверяются локализация сбора, обработчики, уведомления Роскомнадзора, опубликованная политика и применимые основания обработки. Шифрование не заменяет локализацию.

Рабочий режим требует `ORDER_MODE=live`, сильный пароль, `ORDER_ENCRYPTION_KEY` из 64 шестнадцатеричных символов и абсолютный `ORDER_DATABASE_PATH` на постоянном диске. `ORDER_STORAGE_DURABLE=1` — заявление оператора о настроенном постоянном хранилище, а не автоматическая проверка диска. Временная папка блокируется. Платный диск, резервное копирование, восстановление, мониторинг и правила хранения персональных данных должны быть настроены и проверены отдельно. Один экземпляр сервиса: файл SQLite нельзя использовать как общую базу нескольких инстансов.

Контактные данные в рабочем режиме шифруются AES-256-GCM; ключ нужно хранить отдельно и резервировать вместе с доступами. Потеря ключа означает потерю доступа к контактам. Кабинет показывает последние 40 записей выбранного статуса; это демонстрационный журнал, не полноценная система управления рестораном.

Демонстрация обозначена на каждом экране и исключена из поисковой индексации. Наличие пометки не заменяет разрешение правообладателей на бренд, фото и материалы: до рабочего запуска и публичного кейса права согласуются письменно.
